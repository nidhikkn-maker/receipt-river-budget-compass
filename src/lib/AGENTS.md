# Finance rule modules
- Phone notification choices live in owner preferences and notification-settings.ts; funding pushes use independent daily device claims so earlier payment reminders cannot suppress them.
- Subdirectories hold the rest of these notes: src/lib/statement-pipeline/AGENTS.md (statement, import and transfer rules) and src/components/AGENTS.md (review, claim, trip and report rules).
- payees.ts stores external directory records in owner preferences; explicit selection fills the existing merchant draft only, never an owned account or automatic financial classification. Directory changes do not relabel old ledger records.
- correction-fields.ts derives draft account fields from ledger movement/target rules; it never changes financial treatment or substitutes external payees for owned accounts.
- V5.4 financial audit fixtures run only in memory; defect regressions assert real passing outcomes, and unresolved expected failures must never be counted as successful acceptance.
- Position reimbursement totals use outstandingOf on tracked expense claims; legacy workspace reports use workspaceParts, and manual loan splits use stored-INR repaymentParts while preserving principal-only legacy/EMI entries.
- Family permission SQL has an isolated PGlite regression covering active, unrelated and revoked requesters plus owner decisions; cloud tests must never create sample records in production.

- Personal/family tracker, no approvals: expense rules live as pure tested functions in src/lib/expenses.ts.
- Accounts/ledger rules (balances, cashflow, net worth) are pure tested functions in src/lib/ledger.ts; balances are derived from entries, never stored, and transfers/card payments never count as income or spending. store.expenses = expense-type only; store.transactions = all entries.
- Planning math (recurring schedule, forecast, safe-to-spend, loans, goals, subscription detection) lives in src/lib/planning.ts; src/lib/position.ts combines records into screen/AI figures. The AI assistant (src/lib/assistant.functions.ts) only explains facts from position.ts — never let it compute numbers.
- Mutual fund portfolio charts use pure tested rules in src/lib/portfolio.ts on owner-visible NAV snapshots; gain is change since the first saved NAV net of ledger flows, not lifetime return, because acquisition cost is not recorded.
- Long-range predictions are pure tested rules in src/lib/projection.ts (editable category inflation assumptions); suggestions are rule-based from those figures, not AI, so numbers stay verifiable.
- Financial inbox, data freshness and balance-discrepancy checks are pure derived rules in src/lib/inbox.ts; items are never stored, only dismissals, so they clear automatically when records are fixed and discrepancies never auto-create entries.
- Reimbursement claim detail lives in expenses.reimbursement (src/lib/reimbursements.ts); money back is a linked reimbursement-type entry, never income, and reimbursement_status is derived from it.
- Health score (src/lib/health.ts) and monthly review figures (src/lib/monthly-review.ts) are computed by tested rules; the AI only narrates saved reviews, which store a data hash to flag outdated reports.
- Phase 2/3 rules (simulator, behaviour, emergency fund, irregular bills, milestones, trips, merchants, weekly brief) are pure tested functions in src/lib/intelligence.ts; their settings live in finance_preferences, trips link entries by a 'Trip: <name>' tag so stored INR and exchange rates are never rewritten, and simulations never write records unless the user explicitly saves a planned commitment.
- Saved payment methods (UPI IDs, cards, wallets, cash) live in owner-scoped finance_preferences.paymentInstruments with pure tested rules in src/lib/payment-instruments.ts; each is linked to an account of a compatible kind and entries keep the method id plus the general payment type, so balances still flow through the linked account.
- Currency conversion happens server-side in src/lib/fx.functions.ts (Frankfurter/ECB rates for the bill date) so stored INR amounts can't be faked by the client.
- Reports are generated in the browser (src/lib/reports.ts) from data the user can already see, so RLS scoping applies automatically.
- Receipt reading uses the AI Gateway SDK in receipt-extract.functions.ts with the shared receipt-reading.ts schema; subtotal/tax/tip arithmetic is checked at review and server save, items are opt-in line totals, field certainty stays separate and scanned categories require owner confirmation, so extraction never silently changes spending. Rounding to a whole unit (INR/JPY/KRW/IDR, gap under one unit) is accepted as implied round-off and saved as roundOff; printed round-off lines are read separately; decimal currencies stay exact. Low-confidence item fields must be acknowledged in review before confirming (acknowledgement is bound to the exact values, so any edit asks again), while item-vs-subtotal differences stay a review prompt that never blocks saving or later editing.
- Vault document scanning uses a server function (src/lib/document-extract.functions.ts) gated by the same AI privacy settings; extracted fields are always reviewed before saving.
- Category splits live in expenses.allocations and all category reporting goes through categoryTotals/categoryParts so a split transaction is counted once.
- Mutual fund NAVs are authenticated server-fetched daily quotes; reviewed units create dated valuation snapshots, never income or expense entries, so net worth reuses the ledger engine.
- Universal entry presentation rules (recent-first ordering, which detail groups show, date shortcuts) are pure functions in src/lib/entry-form.ts; they never decide amounts or what is saved, so the one save path stays unchanged.
- correction-fields.ts TXN_INTENTS maps the 13 "What is this transaction?" choices onto existing ledger types; loans/advances use receivable or borrowing accounts, reimbursement stays in the claim flow.
- Recipient links: expenses.payee_id references an owner-preferences payee (bulk via apply_review_metadata 'payeeId'); money lent/borrowed with outsiders is an other_asset/other_liability account with details.payeeId, moved by transfers so it never counts as spending or income.
- Expense drafts live in owner-RLS expense_drafts (src/lib/drafts.ts) with receipts under the owner receipts prefix; drafts never enter the ledger, share their id with the eventual transaction so a repeated Save is idempotent, and are marked saved (files removed) after the real save. Every draft edit is first written to an encrypted owner-bound device copy (offline.ts snapshots store) and synced on start-up/online with newer-copy-wins, so offline edits survive closing the app.
- Device MPIN (src/lib/mpin.ts) is a device-only quick unlock: salted PBKDF2 hash per owner in local storage, erased after five wrong tries; it only opens an existing session, never signs in.
- Smart defaults per field and per-shop rules (shopRules keyed by trimmed lower-case shop name, shopAliases mapping other spellings to that key via resolveShop) are owner preferences applied before suggestions reach New expense; a self-picked account is never replaced.
- Offline receipt photos (src/lib/offline-scan.ts) can be dropped from this phone one by one or all failed at once; only photos still waiting to be read are removable, a photo already read stays in Drafts, and every attempt writes back only while the photo is still pending so a late-finishing read can't resurrect one the owner removed.
- Receipt corrections: correctedFields compares the edited bill check against the saved reading (both kept in the draft), and a corrected field counts as owner-checked; only shop-name corrections are learned (shopAliases misread→corrected key via learnedShopName), never amounts or dates.
- Upcoming payments are marked done via mark-done.ts (only an active commitment's current or overdue due date, once each); bulk uses scheduled amounts through confirmCommitment after an in-app confirm.
- Company/person profiles (src/lib/entities.ts) live in owner preferences.entities; PAN type letter and GSTIN embedded PAN/mod-36 check are validated before save, and financial-year status is counted from saved records only, never marked complete automatically.
- Supplier/missing-invoice checks (src/lib/gst-recon.ts) are read-only over business-scope spending; a bill counts if the entry has a receipt or a DocuRepo document linked to it, and GSTIN is read only from linked documents.
- Property/fixed assets (src/lib/assets.ts) live in owner preferences.assets; book SLM/WDV is day-prorated, tax WDV uses block rates with the under-180-day half-rate rule, land never depreciates, and rent checks only read income entries naming the property.
- Income tax/GST working (src/lib/tax-summary.ts) is a read-only per-FY draft from ledger entries and assets; GST input counts only tax printed on business bills, never claimable credit.
