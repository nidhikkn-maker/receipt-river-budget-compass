## 4. Proposed sequence (for KK approval; nothing started)

Small, isolated, tested commits on a preview branch. Before each batch: REQ IDs, screen IDs, dependencies and non-regression tests. Gate order follows V3.1 §13.

**Phase 0: security minimums (before any feature work)**
1. **S1, team-role scoping (H-1, DN-05):**
   - Read-only role-holder query (if approved).
   - Migration restricting `finance`/`manager` reach to explicitly granted entities.
   - Negative-access PGlite tests covering direct IDs, storage, search, exports and jobs.
2. **S2, document ownership (H-3, M-1, M-2):** merge with staged `company-bound-uploads` and `document-storage-boundary` (proposed 0089), fixing the old-owner check.
3. **S3, passkey origin allowlist (M-3)**, plus a test.
4. **S4, session policy (DN-06):** idle timeouts of 5/15 minutes and step-up for approvals and exports. The PIN can never authorise these.
5. **S5, data-deletion coverage (proposed 0092)** and no-silent-delete fixes for assets and holdings.

**Gate 2: finance integrity (after DN-04)**

6. **F1:** the posting layer decision, implemented once with DB-enforced balance, idempotency and period lock, and with tests for reversals and locks.
7. **F2:** statement atomic Undo (proposed 0091) and report history versions (0090).

**Phase 1: first vertical slice (V3.1 §13 "one slice source → books → reconciliation → reports")**

8. **V1, bank month journey (V3.1 journey 2):**
   - statement upload → classification → posting → independent balance reconciliation → reports;
   - with duplicate card debit, partial invoice payment and off-book fee cases;
   - screens D03–D07, C02/C03 (new account detail) and J07.
9. **V2, extraction measurement:** holdout set definition, per-field accuracy with confidence intervals, and an accuracy view (REQ-AUT-001). This needs documents KK approves.
10. **V3, navigation:** restructure to Home/Money/To-do/Records with redirects (DN-03), once the visual direction is confirmed (DN-01/02).

Other feature families wait until V1 passes Gate 4 (one-event cross-module agreement).
